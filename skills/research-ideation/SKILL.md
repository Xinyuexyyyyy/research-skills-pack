# Research Ideation — 发散研究想法

## 定位

从用户给出的模糊方向出发，系统化发散出 3-5 个具体研究 idea 候选。它只负责生成可能性，不负责判断哪个最可行，也不替用户拍板题目。

## 与 topic-framing / idea-to-research 的边界

### 做什么
- 把模糊方向转成多个可讨论的研究 idea
- 选择 2-3 个最适合当前输入的 ideation 框架
- 用框架逐步生成候选 idea，而不是随口列清单
- 为每个候选 idea 写一句话描述和“为什么值得做”
- 把候选 idea 交给 `topic-framing` 做下一步收敛评估

### 不做什么
- 不做可行性排序，不输出最终推荐题目
- 不评估数据、时间、资源、导师偏好等约束
- 不做路线判断，不替代 `idea-to-research`
- 不写开题报告，不设计方法，不检索论文
- 不把 brainstorm 结果包装成已验证 gap

## 上下游关系

- 上游: 用户有模糊方向，但还没有具体题目
- 下游: 候选 idea → `topic-framing` 做收敛评估
- 平级: `idea-to-research` 做路由判断，本 skill 做发散生成
- 输入: 一句话方向、领域兴趣、问题感、技术兴趣或若干零散观察
- 输出: 3-5 个候选 idea，附生成路径和下一步交接提示

## 模式选择

默认先读用户原话，再选 2-3 个框架运行。

| 情况 | 优先模式 |
|---|---|
| 用户已有问题但不知道怎么切入 | 结构化 ideation |
| 用户已有技术/方法但不知道用在哪 | Problem-First vs Solution-First + Composition |
| 用户觉得方向太普通 | 认知引擎模式 |
| 用户提到矛盾、失败、不可兼得 | Tension / Contradiction / Failure |
| 用户想要更跳跃的想法 | Bisociation / Cross-Pollination / Adjacent Possible |

## 结构化 ideation 模式

来自 brainstorming-research-ideas。适合把模糊方向拆成更具体、可命名的研究机会。

| 框架 | 一句话原理 | 3 步 workflow | Self-check |
|---|---|---|---|
| Problem-First vs Solution-First | 从问题或方法两端出发，避免只盯一个入口。 | 写问题 → 写可用方法 → 交叉生成题目。 | idea 是否同时说明“问题”和“方法”？ |
| Abstraction Ladder | 通过上移、下移、侧移改变问题层级。 | 上移泛化 → 下移具象 → 侧移类比。 | 是否产生了不同粒度的候选？ |
| Tension & Contradiction Hunting | 研究机会常藏在不可兼得的目标对里。 | 找目标对 → 写冲突原因 → 设计缓解问题。 | 这个矛盾是否真实存在？ |
| Cross-Pollination | 把一个领域的结构迁移到另一个领域。 | 找源领域 → 抽结构 → 映射到目标领域。 | 类比是结构相似而非表面相似吗？ |
| What Changed? | 旧问题遇到新条件会产生新机会。 | 写旧问题 → 写新变化 → 问现在能做什么。 | 新条件是否真的改变可行性？ |
| Failure Analysis | 从失败案例反推未解决机制。 | 找失败 → 分解原因 → 提出可检验改进。 | idea 是否回应了具体失败点？ |
| Scaling Arguments | 规模变化会暴露原方法的隐藏假设。 | 设 10x 规模 → 找瓶颈 → 生成研究问题。 | 瓶颈是否只在规模变化后出现？ |
| Simplification | 去掉一个假设，可能得到更简洁的问题。 | 列假设 → 删除一个 → 看会破坏什么。 | 被删假设是否值得挑战？ |
| Composition | 组合两个已有方法，观察互补点。 | 选方法 A/B → 找互补 → 定义组合收益。 | 组合是否有新机制，而非拼盘？ |
| Negation | 反转公认假设，寻找反例和边界。 | 写主流假设 → 反转 → 找可测试场景。 | 反转后是否能形成可研究问题？ |

## 认知引擎模式

来自 creative-thinking-for-research。适合突破常规框架，生成更有创造性的候选。

| 框架 | 一句话原理 | 3 步 workflow | Self-check |
|---|---|---|---|
| Bisociation | 连接两个通常不相关的参考框架。 | 选框架 A/B → 找交叉点 → 生成混合问题。 | 两个框架是否真的不常被连接？ |
| Analogical Reasoning | 用结构性类比迁移解释或方法。 | 找源案例 → 抽因果结构 → 映射到目标问题。 | 类比是否保留关键关系？ |
| Constraint Manipulation | 改变约束能暴露新问题空间。 | 列约束 → 加/减/改一个 → 观察新任务。 | 新约束是否改变研究问题？ |
| Inversion | 反转问题方向，寻找被忽略的机制。 | 写原问题 → 反向提问 → 找可验证命题。 | 反向问题是否比原问题更清晰？ |
| Abstraction | 提升抽象层级，看不同现象的共同模式。 | 抽概念 → 找同构案例 → 回落成题目。 | 抽象后是否能回到具体研究？ |
| Boundary Exploration | 在边界条件下测试理论或方法。 | 找边界 → 推演失效 → 设计边界测试。 | 边界是否足够极端且可观察？ |
| Contradiction Holding | 暂时同时持有矛盾命题，逼出新解释。 | 写命题 A/B → 保留冲突 → 找统一机制。 | 新解释是否减少了矛盾？ |
| Adjacent Possible | 在当前能力的一步可达空间里找机会。 | 列已有资源 → 找一步扩展 → 写可做问题。 | idea 是否不是幻想，而是一步可达？ |

## 流程

### Step 1：理解模糊方向
- 用 1-2 句话复述用户想探索的领域、对象或问题感
- 提取关键词、可用材料、明显限制和用户偏好的想法风格
- 如果输入太空，只问 1-3 个缩边界问题

### Step 2：选择框架
- 从两个模式中选 2-3 个最适合当前输入的框架
- 简要说明为什么选这些框架
- 不需要把 18 个框架全部跑一遍

### Step 3：逐个运行
- 每个框架按 3 步 workflow 生成原始 idea
- 合并重复、过宽、不可命名的 idea
- 保留有清晰问题、对象、机制或方法入口的候选

### Step 4：产出候选 idea
- 输出 3-5 个候选 idea
- 每个 idea 用一句话描述
- 每个 idea 写“为什么值得做”
- 标注来自哪个框架或框架组合

### Step 5：交接
- 明确说明下一步交给 `topic-framing`
- 提醒用户此处还没有做可行性评估
- 如果用户要选题，再进入收敛流程

## 产出格式

```markdown
## Research Ideation

### 输入方向
[用户模糊方向的简短复述]

### 本轮使用的框架
| 框架 | 为什么适合 |
|---|---|

### 候选 idea
| # | Idea 一句话 | 为什么值得做 | 来源框架 |
|---|---|---|---|

### 交接到 topic-framing
- 下一步需要评估：可行性、数据可得性、创新空间、资源约束。
- 当前结果是发散候选，不是最终题目。
```
