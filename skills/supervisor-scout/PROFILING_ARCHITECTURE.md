# 导师调研三层画像架构

> **版本**: v1.0
> **生效日期**: 2026-05-13
> **适用范围**: supervisor-scout skill

---

## 一、核心原则

**导师调研是金字塔结构，不需要对所有人做全量画像**：

```
                  ┌─────────────────┐
                  │ Layer 3: 深度画像  │  ← 套磁前最终调研（10-20人）
                  │  10-20分钟/人     │
                  └─────────────────┘
                          ▲
                          │ 筛选
                  ┌─────────────────┐
                  │ Layer 2: 浅层画像  │  ← 初步了解（20-40人）
                  │  2-3分钟/人       │
                  └─────────────────┘
                          ▲
                          │ 筛选
                  ┌─────────────────┐
                  │ Layer 1: 快速筛选  │  ← 海选（100-200人）
                  │  30秒/人          │
                  └─────────────────┘
```

---

## 二、Layer 1：快速筛选

### 目标
从海量导师中筛掉明显不匹配的，缩小到20-40人。

### 单人查询
**WebSearch一次**: `{姓名} 北京理工大学 论文 2025`

### 提取字段
| 字段 | 说明 |
|------|------|
| 姓名 | 必填 |
| 研究所 | 必填 |
| 职称 | 必填 |
| h-index | 如能获取（不要求） |
| 论文总数 | 如能获取（不要求） |
| 2025年活跃度 | 高/中/低/无（**关键字段**） |
| 主要方向 | 1-2个关键词 |
| 特殊状态 | 退休/调离/纯行政等 |
| Layer 2推荐度 | A级（值得）/B级（中等）/C级（暂不） |

### 输出格式
**单一CSV/Markdown表格**，所有导师一行一条。

### 单人耗时
30秒（含WebSearch和提取）

### 批量执行策略
- 每次执行5-10人，避免触发WebSearch速率限制
- 分批保存中间结果，断点续做

---

## 三、Layer 2：浅层画像（当前已做5位）

### 目标
对Layer 1筛出的候选人做基本了解，决定是否值得深度调研。

### 单人查询
**WebSearch两次**:
- 查询1: `{姓名} 北京理工大学 Google Scholar h-index 论文`
- 查询2: `{姓名} 北京理工大学 研究方向 代表性论文`

### 提取字段
| 字段 | 说明 |
|------|------|
| 基本信息 | 姓名、职称、单位、研究所 |
| 学术指标 | h-index、论文数、引用数（如有） |
| 研究方向 | 3-5条主要方向 |
| 代表性论文 | 3-5篇高引论文 |
| 重要荣誉 | 国家级奖项、人才计划等 |
| 综合评级 | S/A/B/C/D（5维度评分） |

### 输出格式
**单独markdown文件**: `profiles/{姓名}_profile.md`

### 评级维度（5维，去掉学生评价）
| 维度 | 权重 |
|------|------|
| 学术产出 | 30% |
| 学术影响力 | 25% |
| 方向匹配 | 25% |
| 招生活跃度 | 10% |
| 学术潜力 | 10% |

### 单人耗时
2-3分钟

## 四、Layer 3：深度画像

### 目标
**套磁前的最终调研**。看导师近2年实际做了什么，而不是简历上写的什么。

> ⚠️ **核心原则**: 研招网官网信息不一定是最新的。导师可能不更新。深度画像必须grab实际最近的论文。

### 四渠道集成

#### 渠道1: Google Scholar 身份页
- **触发条件**: 导师有Google Scholar profile
- **方法**: WebFetch该profile页面
- **提取**: 近2年所有论文列表（标题/期刊/年份/被引数/合作者）
- **优势**: 最准确的学术指标

#### 渠道2: Semantic Scholar API
- **触发条件**: 总是尝试（API免费，无需代理）
- **方法**: 调用 `api.semanticscholar.org/graph/v1/author/search?query={姓名}`
- **提取**: 论文列表、引用、合作者
- **优势**: 覆盖Google Scholar大部分数据，API稳定

#### 渠道3: 学院个人主页
- **触发条件**: 个人主页URL已知（如me.bit.edu.cn下的页面）
- **方法**: WebFetch个人主页
- **提取**: 自我撰写的研究方向、最新论文列表（如果更新）、在研项目
- **优势**: 获取导师自我定位的真实表述
- **风险**: 主页可能多年不更新

#### 渠道4: WebSearch 2025最新动态
- **触发条件**: 总是执行（兜底）
- **方法**: WebSearch `"{姓名}" 北京理工大学 2025`
- **提取**: 最新新闻、报告、获奖、项目动态
- **优势**: 获取学术之外的活跃信号

### 提取字段（核心）
| 字段 | 说明 |
|------|------|
| **近2年论文** | 标题、期刊、年份、被引数、合作者（关键） |
| **近期主题演化** | 从老方向→新方向 |
| **新合作者** | 近期共同作者（可能是学生/博后） |
| **近期项目** | 最近基金中标、产业合作 |
| **个人主页活跃度** | 主页是否半年内有更新 |
| **学术活动** | 近期会议演讲、邀请报告 |

### 输出格式
**深度报告**: `profiles_deep/{姓名}_deep.md`

### 单人耗时
10-20分钟

### 触发条件
- Layer 2评级为S或A
- 用户明确指定的目标导师
- 准备发套磁信前

## 七、各层使用决策树

```
有目标研究方向？
  ├─ 是 → 直接进Layer 2（针对方向匹配的导师）
  └─ 否 → 进Layer 1（海选）

Layer 1筛出名单后
  ├─ S/A级（值得） → Layer 2 浅层画像
  └─ B/C级（一般） → 暂不深入

Layer 2画像后
  ├─ 准备套磁 → Layer 3 深度画像
  └─ 仅了解 → 停在Layer 2

Layer 3完成后
  ├─ 生成套磁信
  └─ 准备面谈话题
```
